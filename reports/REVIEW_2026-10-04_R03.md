# R-03: CLI backend-availability consistency

Based on R-02 commit `53fee87fb96ed557ccbad460cb40aeddd817645a`,
which itself builds on the existing PR #1. This is a separate roadmap card
and change; numerical kernels and backend selection semantics are preserved.

## Reproduced problem

Unlike Mohr, Field Life, Lenia and hybrid runs, Particle Lenia entered its
CUDA/WebGPU runner without checking device availability. Missing devices
therefore raised backend exceptions instead of the CLI's normal exit-code-2
error with install guidance. Unsupported-rule messages also omitted
Particle Lenia, and the WebGPU message omitted hybrid runs.

## Fix and verification

- Check the existing `cuda_available()` / `webgpu_available()` functions
  before Particle Lenia enters a GPU runner.
- Use complete supported-family messages for both GPU flags and the final
  unsupported-config branch; make `--wgpu` help describe all supported kernels.
- Four new CPU regressions failed before the fix and pass after it.
  Missing-device tests force availability false and fail if the runner is
  invoked, so they work even on a GPU-equipped machine without claiming
  hardware verification.
- Particle Lenia suite: **8 passed**.
- Full suite on Python 3.12.14: **82 passed, 40 skipped**.
- `python -m py_compile ece/*.py tools/*.py` and `git diff --check` pass.
- CPU Particle Lenia determinism/gradient/state-export tests remain green.
  No numerical kernel, seed offset or tolerance was changed.
- Documentation and generated handbook refreshed. GPU execution was not
  available; this card tests the missing-device CLI behavior on the CPU.

The session runtime and browser ECE Lab remain absent from the published
repository. R-04 and R-17 remain open for shape and additional config-value
validation, respectively. Check GitHub Actions before merge.
